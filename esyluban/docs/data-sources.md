# 数据从哪来

**默认情况下你不需要读这份文档。** 一张表就是一个 sheet，A1 写 `##export`、B1 写
表名，数据填在下面 —— 这是绝大多数表的样子。

需要读这份，是因为你遇到了下面某一种情况。

---

## 表太大，想拆成几个文件

多个策划同时改一张道具表会一直冲突，拆开就好了。

把它们放进同一个目录，`input` 指向目录：

```
full_name="item.TbItem" & input="item/items"
```

```
DataTables/item/items/
├── 武器.xlsx
├── 防具.xlsx
└── 消耗品.xlsx
```

**目录是递归的**，以后再加文件不用改 B1。新人加一张 `饰品.xlsx` 丢进去就生效。

只有一张表的 A1/B1 需要写元数据（放哪个文件都行），其余文件只填数据。

> 目录里以 `.`、`_`、`~` 开头的文件会被跳过。Excel 打开时生成的 `~$xxx.xlsx`
> 因此不会被误读 —— 但也意味着**目录名不能以 `_` 开头**，叫 `_wip` 的目录会被
> 整个忽略。

如果文件不在同一个目录，用逗号并列：

```
input="item/weapons.xlsx,item/armors.xlsx"
```

**推荐用目录，不用逗号列表。** 逗号列表每加一个文件都要改 B1，而改 B1 需要找到
那张主表 —— 这正是自包含定义想避免的麻烦。

## 一张表的记录分几个 sheet 填

多态表常见：武器、防具、消耗品结构不同但同属一张道具表，分 sheet 填更清楚。

这时 `input` **只写文件路径、不带 sheet 名**，表示读这个文件的**所有** sheet：

```
full_name="item.TbItem" & input="item/道具.xlsx"
```

注意这和上一节的区别：上一节每个 sheet 是**一张独立的表**，这里所有 sheet 合成
**同一张表**。区别只在于 sheet 自己写不写 A1/B1。

只读其中某一个 sheet 时才写 sheet 名：

```
input="武器@item/道具.xlsx"
```

> **`@` 左边是位置，右边是文件** —— 和常见的「文件#锚点」相反。读法是「逻辑上是
> 这张表，物理上躺在那个文件里」，所以逻辑位置写在左边。`luban.conf` 的
> `schemaFiles` 和多语言配置用的是同一套写法。

## 数据不是策划填的，是程序生成的

关卡编辑器导出的关卡、AI 行为树、从后台拉的数值 —— 这类数据用 **json** 比 Excel
合适：工具直接写文件，不用管表格格式。

json 文件通常是这两种形状之一，写法不同：

**一个数组，每个元素是一行**（最常见）：

```json
[ {"id":1, "name":"火球术"},
  {"id":2, "name":"冰箭"} ]
```

```
full_name="skill.TbSkill" & input="*@skill/skills.json"
```

**一个对象，整个就是一行**（配合 `mode="one"` 的全局配置表）：

```json
{ "max_level": 60, "gold_cap": 999999 }
```

```
full_name="common.TbGlobalConfig" & mode="one" & input="common/global.json"
```

**开头那个 `*` 是「这里是数组，每个元素算一行」。** 之所以要你说明，是因为 JSON
没有「表」的概念 —— Excel 的文件结构本身就说明了一行是一行，而
`{"a":1,"b":2}` 到底是一整行还是一组数据，文件里看不出来。

漏写 `*` 的报错很不直观：一个装着 N 行的数组被当成一行解析，错误指向**字段类型
不匹配**，不会说"你少写了个星号"。

工具导出的 json 如果把数据埋在某个字段下，用 `@` 定位到那一段：

```json
{ "version": 3, "levels": [ ... ] }
```

```
input="*levels@stage/stages.json"
```

多层就用 `.` 逐级下钻：`*data.levels@stage/stages.json`。

> Luban 还支持 yaml / lua / xml / csv 做数据源，按扩展名自动识别，写法与 json
> 一致。**除非你有既存资产要对接，否则不建议引入** —— 团队里多一种数据格式，
> 就多一份要教给新人的规矩。

### json 里的多态类型写 `__type__`

同一个数组里混着不同子类型时，用 `__type__` 指明是哪个：

```json
[ {"__type__":"火球术", "damage":100},
  {"__type__":"治疗术", "heal":50} ]
```

Luban 对每种格式另有一个专用键（json 是 `$type`，lua 是 `_type_`），
**但 `__type__` 所有格式都认**。统一写它，以后数据格式换了不用改数据。

## 我加了一张表，但没导出来

EsyLuban 只认一种方式：**sheet 的 A1 恰好是 `##export`，B1 有表名**。
两条都满足才会被扫到。常见原因：

- A1 写成了 `## export`（多了空格）或 `##Export`
- 表所在目录名以 `_` 或 `.` 开头，整个被跳过
- B1 的 `full_name` 与别的表重名 —— 表名全工程唯一

> 用过上游 Luban 的人注意：**文件名以 `#` 开头自动导表的约定在这里不生效。**
> EsyLuban 用 A1/B1 取代了它，原因见[它是怎么工作的](how-it-works.md)。

其余报错见[出错了怎么办](troubleshooting.md)。
