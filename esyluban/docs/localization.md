# 多语言

**给谁看**：程序员。游戏要支持几种语言，玩家能在游戏里随时切换。

**读完你能做什么**：按推荐的做法搭好文本表和校验，知道游戏拿到的产物是什么、怎么按语言取文字；某些数据要按语言分开时，知道要配什么。

**不该在这里找什么**：策划怎么填文字、怎么放几个版本的数据，在[写一张表](writing-tables.md)；报错在[出错了怎么办](troubleshooting.md)。

---

## 它解决什么

同一个游戏要支持中文、英文等几种语言，玩家在设置里一切换，界面和配置里的文字马上换成那种语言。配置表这边有两件事要解决：

1. **文字的翻译。** 道具名、描述、对话，每种语言写法不同，游戏要能随时换。
2. **个别数据跟着语言走。** 比如对话配音、带文字的图片，每种语言用不同的文件。这不是翻译，但也要按语言分开。

国服、海外服这种不同分支的版本不在这里：各分支分别导出，主干的改动靠版本控制合并过去，导表工具不参与。

## 推荐的做法

- 数据表里的文字字段**只填 key**，类型写成 `string#ref=text.TbText`，导出时校验每个 key 都在文本表里。
- 文字写在**文本表**里，文本表和别的表一样原样导出给游戏。游戏显示文字时按当前语言去取；玩家切换语言后刷新界面即可，不用重新导出，也不用重新加载所有配置。
- 文本表有两种组织方式：**一张表、每种语言一列**，或者**每种语言一张表**。按团队怎么翻译来选，见下一节。
- 配音、带文字的图片这类要按语言分开的数据，放进 **`variant_<语言>` 文件夹**，导出时每种语言多出一份产物。每种语言一张文本表，也是这样放的。

## 文本表的两种组织方式

### 一张表，每种语言一列

|  | A | B | C | D |
|---|---|---|---|---|
| **1** | `##export` | `full_name="text.TbText" & read_schema_from_file="true"` | | |
| **2** | `##var` | `key` | `zh` | `en` |
| **3** | `##type` | `string` | `string` | `string` |
| **4** | | `/item_1001_name` | 木剑 | Wooden Sword |
| **5** | | `/item_1001_desc` | 新手用的练习剑 | A practice sword for beginners |

所有语言在同一个文件里。key 只维护一处，翻译的人在同一行看得到原文，漏翻就是一个空格子。只有某种语言才有的文字，加一行、只填那一列。加一种语言要加一列，生成的代码会多一个字段。

游戏拿到的 `text_tbtext.json` 里所有语言都在，按当前语言取那一列。

### 每种语言一张表

```
text/
  texts.xlsx          TbText，默认语言整张：key | value
  variant_en/
    texts.xlsx        TbText，英文整张：key | value
```

每种语言一个文件，翻译按语言分给不同团队时，各自只改自己那一份，互不干扰。加一种语言就是加一个文件夹，生成的代码不变。加一条文字要在每种语言的表里各加一行；某种语言漏了哪个 key，那一条会沿用默认语言的文字，导出时不报错。

这种方式要声明变体（见下面「个别数据要按语言分开」）。导出后 `Generated/Data/text_tbtext.json` 是默认语言的，`Generated/Data/en/text_tbtext.json` 是英文的，游戏切换语言时读对应目录里的那一份。

两种方式里，模块名、表名、列名都可以按项目习惯起，引用它的字段跟着写对就行。文字多了想拆成几个文件，见[数据从哪来](data-sources.md)，一张表可以由多个文件组成。

## 数据表里的文字字段

```
string#ref=text.TbText     必填的文字
string?#ref=text.TbText    可以不填的文字
```

`##type` 由程序员写好，策划只填 key。key 写错、文本表里没有、必填的没填，都会报 `error.validator.ref.not_found`，算校验失败：`check.bat` 和 `--strict` 会以退出码 1 结束。

产物里的文字字段就是 key：

```json
{ "id": 1001, "name": "/item_1001_name", "price": 50, "desc": "/item_1001_desc" }
```

游戏拿 key 去文本表里找到那一行，取当前语言的文字。

## 个别数据要按语言分开

对话配音、带文字的图片这类数据，每种语言用不同的文件。策划把它们放进 `variant_<语言>` 文件夹，怎么放见[写一张表](writing-tables.md#同一张表要有几个版本)。程序员这边做两件事。

**在 `luban.conf` 的 `xargs` 里声明变体：**

```
esyluban.variants=en
```

有几个写几个，逗号隔开。`esyluban.variants` 是 EsyLuban 加的键，上游 Luban 没有。没写它的项目里，`variant_` 只是普通文件夹。

**让游戏读对应的那一份。** 每个变体导出完整的一份：

```
Generated/Data/       默认的一份
Generated/Data/en/    默认数据叠加上 variant_en 里的差异
```

一次导出全部生成，代码只生成一份，`check.bat` 会把每一份都校验一遍。玩家切换到英文时，游戏读 `en` 目录里的那几张表。

哪些数据放进变体、切换语言时重新读哪些表，由项目自己定。变体也不限于语言，任何「同一份数据要有几个版本」的需求都能这样用。

## 为什么不用 Luban 自带的本地化

Luban 的本地化（`l10n.*` 那组配置和 `text` 类型）在导出时就把 key 换成文字，每种语言导出一套数据。游戏要切换语言，就得换一整套配置重新加载。EsyLuban 推荐的做法不用它，`luban.conf` 里也不需要写 `l10n.*`。
