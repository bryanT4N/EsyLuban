# 填列表、字典和嵌套结构

一个格子放一个数字或一句话，这不用教。真正花时间的是**一个字段要放一串东西**：
掉落列表、属性加成、技能的多段伤害。

Luban 给了三种填法。**不是三种风格，是三种适用场合** —— 选错了表会变得没法维护。

---

## 先决定用哪种

| 你要填的东西 | 用哪种 | 长什么样 |
|---|---|---|
| 三五个数字、一个坐标 | **一格，用分隔符** | `1;2;3` |
| 元素有好几个字段，要看清哪列是什么 | **多格** | 每个字段占一列 |
| 元素数量不定，或元素本身就很复杂 | **多行** | 一行一个元素 |

判断依据很简单：**策划改这张表时，眼睛要在哪里找东西。**

- 找一个数字 → 一格就够，多了反而要横着拖
- 要核对"这个掉落的概率是不是填错列了" → 多格，有列标题挡着不会错位
- 要给一个技能加第 7 段伤害 → 多行，直接插一行

---

## 一格，用分隔符

分隔符写在**类型**里：

| ##var | id | drops |
|---|---|---|
| ##type | int | `(list#sep=;),int` |
| | 1 | `101;102;103` |

`(list#sep=;)` 的括号是必须的 —— 它把 `sep` 限定在 `list` 上，而不是元素类型上。
漏掉括号写成 `list#sep=;,int`，`sep` 会挂到元素上，切不开。

> 也可以写在字段名那格（`drops#sep=;`），两种都有效。**推荐写在类型里** ——
> 下面嵌套的例子只有这种写法能表达两层，统一用一种少一个要记的规则。

### 分隔符怎么选

`;` `,` `\|` `_` `-` 都常用。**`#` 和 `&` 要转义**，写成 `\#` `\&` ——
它们在类型串里另有含义。

语料里三种都有：

```
(list#sep=;),int      数据填 1;2;3
(list#sep=\#),int     数据填 1#2#3
(list#sep=\&),int     数据填 1&2&3
```

### 元素本身也有结构时，用两层分隔符

技能的多段伤害，每段是「延迟, 倍率, 描述」：

```
##type   (list#sep=;),SepBean1#sep=,
数据     1,2,abc;20,40,defg
```

**外层 `;` 切出元素，内层 `,` 切出字段。** 读出来是两个对象：
`{a:1, b:2, c:"abc"}` 和 `{a:20, b:40, c:"defg"}`。

两层分隔符必须不同，否则切不开。层数不限，逐层各写各的：

```
(list#sep=|),(list#sep=,),int        数据：1,2|3,4,5
(map#sep=-|),int,(list#sep=,),int    数据：1-1,2,3|2-2,4,6
```

第二行的 `sep=-|` 是**两个字符都能当分隔符**的写法：map 用 `-` 分隔键与值、
用 `|` 分隔每一对。

结构体也可以把分隔符定义在自己身上（`__beans__.xlsx` 的 `sep` 列），
用到它的地方就不必重复写：

```
##type  list,matrix.InnerBean
数据    1:Alpha,2:Beta
```

这里 `:` 是 `InnerBean` 自带的分隔符，外层 `,` 才是这个 list 的。
**坐标、颜色这种到处都在用的小结构，建议这样定义一次。**

### 这种填法有个硬限制

**空格子不能省。** 分隔符格式是顺序读的，靠位置对应字段 —— 少填一个，后面全部
错位，而且往往不报错，只是数据悄悄串了。

所以：**字段超过三四个、或者有可选字段，就别用这种。** 换多格。

---

## 多格：一个字段占几列

字段名那格**横向合并**几列，下面用 `##+` 行写子字段名：

| ##var | id | pos | | |
|---|---|---|---|---|
| ##type | int | Vector3 | | |
| ##+ | | x | y | z |
| | 1 | 10 | 0 | 5 |

`##+` 是**子字段名行**，作用和 `##var` 一样，只是描述的是下一层。
嵌套再深就再写一行 `##+`。

**多格的价值是防错位。** 每一列有自己的标题，策划填的时候看得见"这列是 y"。
分隔符格式没有这个保障。

> csv 没有合并单元格，用 `[字段名` 和 `字段名]` 两个标记框出范围。
> **能用 xlsx 就别用 csv** —— 复杂结构在 csv 里很难维护。

---

## 多行：一行一个元素

字段名前面加 `*`：

| ##var | id | `*drops` | |
|---|---|---|---|
| ##+ | | item_id | count |
| | 1 | 101 | 5 |
| | | 102 | 1 |
| | | 103 | 2 |

第一行填 id 和第一个元素，后面几行只填元素，**id 那列留空**表示还是同一条记录。

`*drops` 是 `drops#multi_rows=1` 的简写，两种写法等价，**推荐用 `*`**。

**元素数量不定的就该用这种。** 加一个掉落 = 插一行，不用改表头；用多格的话，
掉落上限被列数写死了。

---

## 字典（map）

三种填法都能用，区别只在怎么表达「键」。

### 一格：键值交替

| ##var | id | bonus |
|---|---|---|
| ##type | int | `(map#sep=,),int,int` |
| | 1 | `1,2,3,4` |

读出来是 `{1:2, 3:4}` —— **逗号分隔的序列里，奇数位是键，偶数位是值**。

短小的映射用它很省事，但**多了极易数错**。超过三对就换下面两种。

### 多行：用 `$key` 指明键在哪列

| ##var | id | `*bonus` | |
|---|---|---|---|
| ##+ | | `$key` | count |
| | 1 | 101 | 5 |
| | | 102 | 1 |

`$key` 是保留列名，表示这一列是键。

---

## 每种类型字段都不一样：用多态

技能效果有「造成伤害」「施加 buff」「召唤单位」，字段各不相同。

**不要用 `type + param1 + param2 + param3`。** 那样每列的含义随 type 变，
策划要靠记忆填，程序要靠 switch 解析，加一种效果就要动所有地方。

正确做法是让每个子类型只声明自己的字段，填表时用 **`$type` 列**指明这一行是哪种：

| ##var | id | effect | | |
|---|---|---|---|---|
| ##+ | | `$type` | damage | buff_id |
| | 1 | 造成伤害 | 100 | |
| | 2 | 施加buff | | 2001 |

`$type` 填子类型名，**也可以填别名** —— 给子类型起中文别名，策划填中文。

用不上的列留空即可。这正是多态相对 `type+param` 的价值：**每种类型只需要关心
自己那几列。**

> 多行 + 多态可以叠加：一个技能配多段效果，每段类型不同。

## 三种 `##` 行，和几个能省事的写法

表头行的第一格决定这一行是什么：

| 第一格 | 这一行是 |
|---|---|
| `##var` | 字段名 |
| `##type` | 字段类型 |
| `##+` | 子字段名（多格 / 多级标题用） |
| `##group` | 字段分组（客户端/服务端），见[目标与输出](targets-and-output.md) |
| `##` | 纯注释行，**内容随便写**，导出时忽略 |

**这些行的顺序可以随便调。** 靠第一格识别，不靠位置。

### 注释掉一行数据

数据行的**第一格填 `##`**，这一行永不导出。用来临时停用某条配置，比删掉安全 ——
改回来只要删掉那两个井号。

### 注释掉一列

**列名留空，或者以 `#` 开头。** 策划常用来放「备注」「策划自己算的中间值」，
这些列不会进产物。

### 表格文件里放非数据 sheet

草稿、计算过程、给自己看的说明，**只要 A1 不是 `##export` 就不会被导出**。
一个 xlsx 里数据 sheet 和工作 sheet 可以共存。

## 常见的踩坑

**分隔符写在了类型上。** `sep` 写字段名那格：`drops#sep=;`。写到 `##type` 那格
对容器不生效。

**`#` 和 `&` 当分隔符没转义。** 要写 `\#` `\&`。

**用分隔符填了会留空的字段。** 顺序读入不认空格子，数据会串位且不报错。换多格。

**多行的续行填了 id。** 续行除了该字段以外都要留空，填了会被当成新记录。

其余报错见[出错了怎么办](troubleshooting.md)。
