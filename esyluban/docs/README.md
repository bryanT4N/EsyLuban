## 这些文档遵守的几条规矩

写在这里是为了让下一个改文档的人知道边界在哪，也为了让读者知道可以指望什么。

**一份文档 = 一个读者 + 一件事。** 文件名就是那件事。你不该需要目录才能猜对点哪个。

**每个坑只写一次。** 重复的警告说明作者不相信读者能找到前一处 —— 那是信息架构
的问题，不该靠复制粘贴解决。旧版手册里「xargs 没有 `{target}.` 这一层」写了
七遍，措辞还各不相同。

**能被源码证否的说法，都由回归守着。** `scripts/test/check_doc_facts.ps1` 会比对
文档与代码：内置 target 的数量、右键的实现机制、安装器的行为、每个被标注「可
直接照抄」的模板是否真的能用、文档里引用的路径是否存在。这些以前全靠人记得，
而它们已经错过 —— 手册曾把「27 种 codeTarget」和「29 种」写在同一份文件里。

**修复历史写进 [CHANGELOG](../../CHANGELOG.md)，不写进说明书。** 读者要知道的是
「我这版能不能用」，不是某个 bug 的病理报告。
